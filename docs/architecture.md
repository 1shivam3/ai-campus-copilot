# CoursePilot System Architecture

This document provides a technical breakdown of CoursePilot's system architecture, component responsibilities, data flow, offline caching, and algorithmic design.

---

## 1. System Overview

CoursePilot is a full-stack, context-aware academic operating system built for computer science and engineering undergraduates. It connects institutional course schedules and syllabus requirements with individual student workflows (tasks, exams, topic progress, study materials, and flashcards).

## 2. Component Responsibilities

### 2.1 Frontend (`React 19` + `Vite` + `Tailwind CSS`)
- **Single Page Application (SPA)**: Client-side routing with clean state preservation and PWA offline capability.
- **Cache-First Academic Loaders**: Reads timetable, syllabus, and today's schedule instantly from local IndexedDB storage before background online reconciliation.
- **Offline Sync Queue**: Optimistically records local topic mastery changes and flushes pending actions to Supabase upon receiving the `online` event.
- **Document Parsing**: In-browser PDF rendering and text preview via `pdfjs-dist`.
- **Responsive Layout**: Dedicated mobile bottom taskbar (`Home`, `Academics`, `Tasks`, `Progress`, `More`), fluid tablet grids, and desktop sidebar.

### 2.2 Database & Storage Layer (`Supabase` / `PostgreSQL 15`)
- **Authentication**: JWT-based session management and identity verification.
- **Relational Schema**:
  - `student_profiles`: Academic enrollment details (semester, section).
  - `academic_subjects`: Subject codes, course names, and assigned faculty.
  - `class_schedule`: Complete Semester 3 CSE weekly timetable (24 sections, 600 schedule rows, Monday–Friday).
  - `syllabus_topics`: Hierarchical curriculum units and topic descriptions.
  - `student_topic_progress`: Authoritative student mastery ($0\% - 100\%$) across syllabus topics.
  - `tasks`: Student assignments, lab reports, and deadlines.
  - `exams`: Midterms and final exam schedules with academic importance ratings.
  - `study_sessions`: Focus session durations and timestamps.
- **pgvector Vector Store**: 768-dimensional embeddings generated by Gemini `text-embedding-004` stored in `study_material_chunks`.
- **Row-Level Security (RLS)**: Enforces database-level tenant isolation so students can only access their own private data (`auth.uid() = user_id`).
- **Private Storage**: User-scoped storage buckets for uploaded lecture notes and past question papers.

### 2.3 Backend API Layer (`FastAPI` + `Python 3.12`)
- **Secure AI Proxy**: Keeps Google Gemini API keys server-side, preventing exposure to client browsers.
- **Document RAG Pipeline**: Extracts PDF text, applies semantic chunking (2,400 chars, 400 overlap), computes vector embeddings, and performs cosine similarity retrieval via `match_study_material_chunks`.
- **Study Pack & Flashcard Generators**: Transforms raw lecture notes into structured 7-part study packs and SM-2 spaced repetition cards.
- **Previous-Year-Paper Analyzer**: Parses exam papers for topic weightage, question taxonomy, and revision priority.
- **Cross-Device XP Sync**: Deduplicates and unifies student XP transactions across devices using deterministic transaction keys.
- **Security Middleware**: Injects strict security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`).

## 3. RAG Retrieval Pipeline Flow

```text
Student Uploads PDF Document (Lecture Notes / Question Paper)
                    │
                    ▼
          Text Extraction (pypdf)
                    │
                    ▼
     Semantic Chunking (2,400 chars, 400 overlap)
                    │
                    ▼
  768-dim Embeddings (Gemini text-embedding-004)
                    │
                    ▼
     PostgreSQL pgvector (study_material_chunks)
                    │
                    ▼
      User Asks Question in Document Reader
                    │
                    ▼
Vector Cosine Similarity Search (match_study_material_chunks RPC)
                    │
                    ▼
   Top Ranked Relevant Passages + Page Numbers
                    │
                    ▼
   Grounded Synthesis with Gemini 2.5 Flash
                    │
                    ▼
   Direct Answer with Page-Level Source Citations
```

## 4. Offline Data Synchronization Flow

```text
               User Disconnected (Offline)
                           │
                           ▼
            Student Updates Topic Mastery
                           │
                           ▼
          Save to IndexedDB (Dexie) Immediately
          • status: "learning"
          • pending_sync: true
          • Append to sync_queue
                           │
                           ▼
            UI Renders Instant Update (0ms)
            • Displays "Pending sync" Badge
            • Top Nav Displays "Offline"
                           │
                           ▼
               User Reconnects (Online)
                           │
                           ▼
         Window Event: "online" Triggered
                           │
                           ▼
               processSyncQueue(userId)
          • Reads pending items from sync_queue
          • Performs Upsert to Supabase
          • Removes items from sync_queue
          • Clears pending_sync flag
                           │
                           ▼
            UI Auto-Updates to "✓ Synced"
```

## 5. Deployment Topology

| Component | Platform | Configuration |
| :--- | :--- | :--- |
| **Frontend** | Vercel | Automatic production deployments, SPA rewrite rules, production security headers. |
| **Backend** | Render | FastAPI web service running on Python 3.12 runtime with Uvicorn ASGI. |
| **Database & Storage** | Supabase | Managed PostgreSQL 15 instance with RLS, pgvector, and private storage. |
| **AI Models** | Google Cloud | Gemini 2.5 Flash and text-embedding-004 models. |
